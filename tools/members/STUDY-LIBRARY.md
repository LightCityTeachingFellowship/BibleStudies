# Site-wide study library

## What ships

- Articles and every summary template receive bookmark, Continue reading and Mark as read controls.
- `/MyVideos/` remains the stable address and becomes My study library, with shared Saved/History tabs and All, Videos & audio, Articles and Summaries filters.
- Home shows up to six recent unfinished readings/videos/audio recordings. It does not start playback.
- Related study resources appear below readings and on Watch. Explicit shared video IDs or `study_id` groups are preferred. Title-derived suggestions are labelled as such.
- Reading bookmarks are also available beside publication search result titles.

## Publishing

1. Commit/sync the website changes so `/study-catalog.json` is generated by GitHub Pages. It must return JSON with a nonempty `publications` array.
2. From `tools/members`, deploy only the two new account functions:

```powershell
$env:FUNCTIONS_DISCOVERY_TIMEOUT = "60"
firebase deploy --only "functions:lightcity-members:getMyReadingActivity,functions:lightcity-members:updateMyReadingActivity" --project perceptive-zoo-424115-j6
```

The reading feature keeps local per-device/per-account changes queued while these endpoints are unavailable. After deployment they retry on the regular sync timer, on reconnect or after reopening the page. Publishing the site first ensures that the backend can validate the reading catalogue.

Member-only reading metadata is generated into the server-only `functions/reading-private-catalog.json` by the Firebase predeploy hook. The preparer reads member-flagged article/summary front matter and requires explicit permalinks. Approved member accounts fetch that metadata through `getMyReadingActivity` with `view: catalog`; it is held in memory and is not stored in the public catalogue cache. New or changed member publication metadata requires redeploying the two reading functions. The frontend clears private catalogue entries on account changes, and the backend rechecks membership before returning or writing private reading activity.

No new Firestore rules are required if the existing `firestore-personal.rules` exclusion for `churchVideoActivity` has already been deployed (as for video history). Reading data lives under that same protected collection, in `readingSaved` and `readingHistory` per UID. Only callable functions access it. Never add direct client read/write grants.

## Curated connections

Add matching `study_id` values to the front matter of an article and its summaries for an explicit shared teaching group, for example:

```yaml
study_id: understanding-the-atonement
video_ids:
  - YOUTUBE_ID1
```

Replace the example with actual 11-character IDs. Existing YouTube embeds/links are also inspected when generating the catalogue. Only IDs in the public website list and absent from the members list are emitted in this public JSON. Member video title suggestions are computed only from the approved library already available to that user. Public catalogue entries contain only reading titles, URLs, kind, group and public connection IDs, never article bodies or account activity.

Curated resource metadata is more reliable than title similarity. A suggested related resource is not a verified transcript or summary of a particular recording.

## Reading progress and privacy

Positions are saved at paragraph/heading boundaries after user interaction and ten seconds on the page, then on scroll (throttled), periodic sync, hiding and leaving. Continue reading uses a deliberate link/button rather than unexpectedly scrolling a normal article visit. Collapsed details can reopen when resuming. Mark as read is explicit; reaching the end while actively reading can also mark completion.

Guests save on the device. Signed-in users have separate account-scoped caches and a durable outbox. Device data is copied to an account only through the existing explicit Copy device saves & history button. Clear history covers video/audio and reading but preserves bookmarks. Accounts are verified by the backend, and account UID mismatch is rejected. The backend derives IDs and valid publication membership from the published trusted catalogue plus its server-only member catalogue; caller URLs and titles are not accepted as authority.

Reading keys depend on canonical published URL paths. If a publication permalink changes, its old position does not automatically migrate. Editing/reordering paragraphs can shift the resume point; it is not a character-exact cursor. Browser storage removal deletes unsynced device-only data. Resource links are rechecked against current catalogue/member access before rendering.
